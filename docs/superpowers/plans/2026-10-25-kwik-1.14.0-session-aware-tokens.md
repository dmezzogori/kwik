# kwik 1.14.0 Session-Aware Tokens Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship kwik 1.14.0 with session-aware bearer tokens (a session claim, refresh with rotation, reuse detection with a 30 s grace window, a per-request revocation hook an application implements against its own session table), impersonation that opens a session, bearer dependencies no longer tied to the OAuth2 password form, and a test client that mints tokens instead of posting the password form, while a kwik 1.13 application that configures nothing keeps its current behaviour; plus the three fixes of kwik#43 (secrets out of the debug log, inactive accounts refused, timezone-aware API-key expiry) and an upgrade of the locked dependencies that clears the 43 open Dependabot alerts (owner decisions 6–9).

**Architecture:** kwik keeps owning token creation and decoding (`kwik/security.py`) and adds a small `kwik.auth` package: an `AuthSession` record, an `AuthSessionStore` protocol the application implements (kwik ships an in-memory store for tests and single-process apps), and the service functions that open, refresh, revoke and check sessions. Sessions are *opt-in*: a `Kwik` app constructed without a store (or whose store dependency resolves to `None`) issues and accepts 1.13-style tokens; a store turns on the session claim, refresh, logout and the per-request check. The bearer dependencies read the `Authorization` header through `HTTPBearer`, answer 401 with `WWW-Authenticate` per RFC 6750, and keep the names Teban imports (`get_token`, `_get_current_user`, `_resolve_current_user`).

**Tech Stack:** Python 3.12, FastAPI 0.140.7 (`fastapi.security.HTTPBearer`), PyJWT 2.15 or later once Task 0A has run (HS256; 2.13.0 is locked today), SQLAlchemy 2 (unchanged; kwik adds no table), Pydantic 2, pytest + xdist + testcontainers, uv, ruff (ALL rules).

**Spec:** `~/Developer/teban/docs/superpowers/specs/2026-10-24-sign-in-and-identity-design.md` (§ Constraints, kwik release; § Decisions: Tokens, Browser sessions, Revocation; § Behaviour › Sessions; § Left to the builder). Programme order: `~/Developer/teban/docs/superpowers/specs/2026-10-25-v3-programme-overview.md` (kwik release first). Both are read-only from this repository.

Both are listed under Changed (breaking) in Task 8.
- Pushing `main` and the tag `v1.14.0` requires Davide's explicit go-ahead (Task 8); this plan never pushes, tags or publishes.

## Owner Decisions (Davide, 2026-10-25)

Taken on the planner's handoff; they are decided, not open, and every task below follows them. Decisions 6–9 were added by the owner on 2026-10-27.

1. **Invalid, expired or revoked bearer tokens answer 401** with `WWW-Authenticate: Bearer error="invalid_token"` in 1.14 (was 400 from `TokenValidationError`). `decode_token` itself still raises `TokenValidationError` for library callers. Tasks 2, 3, 8.
2. **`_resolve_current_user` takes a required `store` keyword.** A loud break for applications that call it directly from an override (Teban's `active_user.py`); no `None` default. Tasks 3, 8.
3. **`ACCESS_TOKEN_EXPIRE_MINUTES` keeps its 10_080 default.** Applications that enable sessions set it to minutes; the handbook says so. Tasks 1, 7.
4. **Names `kwik.auth`, `AuthSession`, `AuthSessionStore`, `InMemoryAuthSessionStore`** stand. Task 2.
5. **kwik carries the refresh token in the JSON body only.** The HttpOnly cookie transport (spec § Decisions, Browser sessions) is Teban's thin route over `refresh_session`. Task 4.
6. **1.14.0 widens to all of kwik#43 and the open Dependabot alerts** (owner, 2026-10-27). The three items of kwik#43 ship in this release, each as its own commit (Tasks 0B, 3 Step 6, 3A), and the 43 open Dependabot alerts, all in `uv.lock`, are cleared by upgrading the locked versions (Task 0A). The Teban side (dropping `dependencies/active_user.py`'s overrides, migrating Teban's `api_keys` table) is Teban's sessions plan, never edited from here.
7. **kwik enforces `User.is_active`** (owner, 2026-10-27; kwik#43 item 2). `_get_current_user`, the bearer path of `_resolve_current_user` and `authenticate_from_token` judge the *acting* account: under impersonation the impersonator must exist and be active and the impersonated account may be inactive (an administrator inspecting a deactivated account); otherwise the user must be active. A refusal is `InvalidBearerTokenError(detail="Inactive user")` (401). `crud_users.authenticate` refuses an inactive account with `AuthenticationFailedError`, the wrong-password answer, so the response does not reveal the account state. The API-key path is unchanged (it already refuses an inactive owner). Breaking for applications that relied on inactive users authenticating.
8. **API-key timestamps are timezone-aware** (owner, 2026-10-27; kwik#43 item 3). `ApiKey.expires_at`, `revoked_at` and `last_used_at` become `DateTime(timezone=True)` and `verify_api_key` compares with `datetime.now(UTC)`; `created_at` keeps its type (the database writes it, nothing compares it). kwik ships no migrations, so the CHANGELOG carries the Alembic snippet an application runs (Task 8).
9. **Secrets leave the debug log by redaction, not `SecretStr`** (owner, 2026-10-27; kwik#43 item 1). Making `SECRET_KEY` and the passwords `SecretStr` would change their type for every application that reads them as strings (Teban signs its challenge, MCP and cookie tokens with `settings.SECRET_KEY`); a redacted dump at the one log site fixes the leak without an API change (Task 0B).

## Review Focus

1. A refresh token presented *after* the grace window, when it is the previous generation of a live session, is reuse: the session is revoked and every access token carrying its `sid` stops working on the next request. Pinned in Task 2 (`test_refresh_previous_after_grace_revokes_session`) and Task 4 (`test_access_token_rejected_after_reuse`).
2. Two tabs refreshing the same token inside the grace window both receive the *same* refresh token string and valid access tokens, and neither sign-out happens. Pinned in Task 2 (`test_refresh_within_grace_returns_identical_successor`, and `test_lost_rotation_race_takes_grace_path` for two requests that race on the same current token).
3. A refresh token sent as a bearer credential, or an access token sent to `/login/refresh`, is refused with 401, never accepted because the signature verifies. Pinned in Task 1 (`test_decode_token_rejects_other_type`) and Task 4 (`test_refresh_rejects_access_token`, `test_bearer_rejects_refresh_token`).
4. When a store is configured, a token without `sid` (a 1.13 token still held by a browser at rollout) is refused with 401; when no store is configured, a token with `sid` is accepted and the claim is ignored. Pinned in Task 3 (`test_store_rejects_token_without_sid`, `test_no_store_ignores_sid`).
5. An impersonation session refreshed after the administrator's own session was revoked does not survive: refresh of the child is refused once the parent is revoked, and `stop_impersonating` refuses to open a new administrator session. Pinned in Task 5 (`test_refresh_child_refused_after_parent_revoked`, `test_stop_impersonating_refused_when_parent_revoked`).

@dataclass
class AuthSession:
    """One signed-in session; the application persists it (kwik adds no table)."""
    id: str
    user_id: int
    created_at: datetime
    expires_at: datetime                 # refresh expiry, whole seconds; moved forward on every rotation
    refresh_token_id: str                # jti of the current refresh token
    impersonator_user_id: int | None = None
    parent_session_id: str | None = None  # the impersonator's session, for impersonation sessions
    previous_refresh_token_id: str | None = None
    rotated_at: datetime | None = None
    revoked_at: datetime | None = None

    def is_active(self, *, now: datetime) -> bool: ...   # revoked_at is None and expires_at > now


class AuthSessionStore(Protocol):
    """What an application persists. Every datetime is tz-aware UTC. ``get`` runs on every authenticated request."""
    def create(self, session: AuthSession) -> None: ...
    def get(self, session_id: str) -> AuthSession | None: ...
    def update(self, session: AuthSession) -> None: ...   # application use: hard caps, revoke-on-deactivation; never called by refresh_session
    def rotate(self, session_id: str, *, expected_token_id: str, new_token_id: str,
               expires_at: datetime, rotated_at: datetime) -> AuthSession | None: ...
        # compare-and-set: only if the record's refresh_token_id == expected_token_id, set
        # previous_refresh_token_id=expected_token_id, refresh_token_id=new_token_id, expires_at, rotated_at,
        # and return the new record; return None when another rotation won (one UPDATE ... WHERE ... RETURNING in SQL).
    def revoke(self, session_id: str, *, at: datetime) -> None: ...  # the session and every session whose parent_session_id is it


class InMemoryAuthSessionStore:  # implements AuthSessionStore; dict keyed by id; for tests and single-process apps
    ...

def require_active_session(*, payload: TokenPayload, store: AuthSessionStore | None,

```python
def refresh_session(*, refresh_token, settings, store, now=None) -> Token:
    now = now or datetime.now(UTC)
    payload = decode_token(token=refresh_token, settings=settings, token_type="refresh")   # TokenValidationError -> InvalidBearerTokenError
    record = store.get(payload.sid) if payload.sid else None
    if record is None or not record.is_active(now=now):
        raise InvalidBearerTokenError
    if payload.jti == record.refresh_token_id:                       # current generation: rotate (compare-and-set)
        rotated = store.rotate(record.id, expected_token_id=payload.jti, new_token_id=_new_id(),
                               expires_at=_whole_seconds(now + timedelta(minutes=settings.REFRESH_TOKEN_EXPIRE_MINUTES)),
                               rotated_at=now)
        if rotated is not None:
            return _pair(rotated, settings)
        record = store.get(record.id)                                  # another request rotated first: fall through to the grace check
        if record is None or not record.is_active(now=now):
            raise InvalidBearerTokenError
    grace = timedelta(seconds=settings.REFRESH_REUSE_GRACE_SECONDS)
    if payload.jti == record.previous_refresh_token_id and record.rotated_at is not None and now - record.rotated_at <= grace:
        return _pair(record, settings)                                 # same successor: claims re-minted from the record, identical string
    store.revoke(record.id, at=now)                                    # reuse: the whole session dies (spec § Decisions, Tokens)
    raise InvalidBearerTokenError(detail="Refresh token reused; session revoked")
```

`_pair(record, settings)` = `create_token(user_id=record.user_id, impersonator_user_id=record.impersonator_user_id, session_id=record.id, settings=settings)` with `refresh_token=create_refresh_token(user_id=record.user_id, session_id=record.id, token_id=record.refresh_token_id, expires_at=record.expires_at, settings=settings)`. `_whole_seconds(dt)` is `dt.replace(microsecond=0)`: `expires_at` becomes the `exp` claim, which PyJWT encodes as whole seconds, so the record stores what the token says and the grace-window re-mint is identical; `rotated_at` and `created_at` keep full precision. `open_session` builds the record (`created_at=now`, `expires_at=_whole_seconds(now + REFRESH_TOKEN_EXPIRE_MINUTES)`, a fresh `refresh_token_id`), raises `ValueError` when `impersonator_user_id` is given without `parent_session_id`, calls `store.create`, returns `_pair`. `InMemoryAuthSessionStore.rotate` runs under a `threading.Lock` and compares before writing, so it is a faithful compare-and-set; the handbook tells SQL stores to write it as one `UPDATE ... WHERE id = :id AND refresh_token_id = :expected RETURNING *`. A refresh that reaches `require_active_session`-style checks with naive datetimes is a store bug: every datetime in a record is tz-aware UTC. `require_active_session`: `None` store → `None`; `payload.sid is None` → `InvalidBearerTokenError`; `payload.typ != "access"` → `InvalidBearerTokenError`; `store.get` missing or inactive → `InvalidBearerTokenError`; else the record. `revoke_session` → `store.revoke(session_id, at=now)`.

The 90-day hard cap from the spec is not a kwik setting: an application enforces it in its store's `get`/`update` (refuse to extend `expires_at` past `created_at + 90 d`), and the handbook (Task 7) says so.
